# AI 去重辅助与系列检查

## 使用

1. 在设置或审核窗口的「AI 辅助判断」中选择 AI 服务：兼容 API、ChatGPT (JSON)、ChatGPT (Account)。三种方式分别保留模型选择；切换服务保留原 API 地址和加密 Key。没有服务类型的旧配置自动作为兼容 API 使用。
2. 兼容 API 填写服务地址和 API Key。地址接受 `https://provider.example/v1` 或完整的 `/chat/completions` 地址；本地免鉴权服务可以留空 Key。点击「获取模型」，从可搜索的下拉列表选择，也可以直接输入模型名，再测试连接、保存并启用。
3. 兼容 API 默认使用严格 JSON Schema。DeepSeek 官方对话接口自动选择其支持的 JSON 对象模式，设置页同步显示实际格式；其他上游可手动选择。JSON 对象模式也会发送完整格式定义并在本地校验。上游明确拒绝输出格式时，界面会提示切换格式；其他 HTTP 400 不自动重试或切换协议。
4. 在重复组内点击「AI 分析本组」，或分析当前整份重复报告。结果在原组内显示，不改变保留勾选、队列顺序和原有审核结论。
5. 「重复检查」的检查范围下拉框提供「AI 全库分析并查重」。选中后点击同一个开始按钮，应用会完成全库语义整理、关系判断和一次完整本地重复检查，完成后刷新重复审核报告。只有全库单本解析与候选配对判断全部完成，才会自动进入本地核验；AI 部分失败、遗漏或取消时保留成功缓存，并提示继续处理剩余项。AI 只提交本轮成功的同作关系，系列关系、不同期刊物关系和不确定关系不会进入重复队列。
6. 「系列检查」独立展示作品系列、卷话顺序、不确定关系和刊物期次。该结果不能用于隔离文件。

兼容 API 的「获取模型」使用当前填写的地址和 Key 请求上游 `/models` 接口；Key 留空时使用已保存的 Key。不需要先保存或启用 AI，也不需要先填模型。获取列表不会修改已选模型或保存配置。上游未提供模型列表时可以手动输入；列表包含的模型是否支持当前分析协议，仍需通过「测试连接」确认。

### ChatGPT (JSON)

在输入框粘贴完整 OAuth JSON，点击「校验并导入」。接受顶层字段以及 `tokens` 嵌套字段。旧 Codex 凭据需有 `access_token`、`account_id`，可附带 `refresh_token`、`id_token`、`client_id`、到期信息；新 SIWC 凭据还需实际注册的 `client_id` 和 `chatgpt.tokens.use.direct` 授权。应用识别类型后使用对应协议，不把 OAuth 令牌写入 API Key。

导入成功表示格式和保存成功，仍需获取模型、选择模型并测试连接。只有完成推理并校验结果后才显示本次连接验证成功。失败的替换保留旧凭据，成功后清空粘贴框；已保存令牌不回填。

界面显示是否支持自动续期。已识别原始 Codex 客户端或完整 SIWC 注册的凭据可续期；缺少客户端信息或仅有访问令牌时，到期需重新导入或网页登录。应用不会猜测未知刷新客户端。旧 Codex 凭据直接使用公开 Codex 源码对应的原生请求协议，兼容性会随上游变化，不依赖额外 Codex 子进程。

### ChatGPT (Account)

点击「通过网页登录」，在系统浏览器完成 Codex 原生 ChatGPT 登录。主进程使用 Codex 的固定客户端、`/oauth/authorize`、PKCE 和 `127.0.0.1` 回调，验证 state、nonce、签名、受众及账户身份后保存新账户。登录期间可以取消或重新打开浏览器；关闭设置窗口不会取消登录。切换失败保留旧账户，成功后重新获取模型并测试连接。此前通过 SIWC 动态注册保存的 Account 登录需要重新登录，应用不会将旧授权令牌发送给 Codex 接口。

原生网页登录和 Codex JSON 使用 Codex 独立端点及账户请求头；JSON 导入仍可识别 SIWC 格式，并使用其公共 Responses API。请求均发送 `store:false`、`stream:true`，按账户返回的可展示模型填充下拉框，显示名称与实际请求 ID 分开。接收到完整 `response.completed` 并解析 JSON 后才算成功；中断、拒绝和额度错误不能作为成功结果。已开始返回的推理流不会自动重放。401 在推理流开始前最多续期并重试一次；令牌刷新会串行保存旋转后的刷新令牌。

登录、取模型和令牌刷新均按需进行，启动主界面不等待这些网络请求。授权过期、缺少权限或额度不可用会停止当前分析批次，保留已完成结果。Account 退出登录尝试撤销本应用的网页登录会话后清除本地令牌，无法确认远端撤销时单独提示。清除 Codex JSON 仅清除本应用导入的副本，保留来源工具的登录会话。

原生登录参考：[Codex 身份验证](https://learn.chatgpt.com/docs/auth)。SIWC JSON 参考：[模型和推理](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference)、[账户和续期](https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions)。

### 账户、额度与思考程度

两种 ChatGPT 方式显示账户邮箱、最近登录或导入日期、凭据到期及续期状态。JSON 中的邮箱属于导入信息，只有完成签名和身份校验才标为已验证身份；未知邮箱与日期保持未知。

额度卡显示主窗口和周窗口的剩余百分比、重置时间及最近刷新时间，窗口时长以服务返回值为准。点击「刷新额度」通过当前服务的独立凭据读取 Codex 用量接口，与书籍分析独立。缺失窗口或百分比显示未知；刷新失败保留错误状态，不把失败解释为零额度。SIWC JSON 不支持此额度接口，界面提供「打开用量页面」。退出或替换凭据会清理上一账户的额度状态。

ChatGPT 支持低、中、高、极高、Max、Ultra 六档思考程度，默认中。实际请求分别传入 `reasoning.effort` 的 `low`、`medium`、`high`、`xhigh`、`max`、`ultra`，不以其他档位代替。模型目录明确提供能力时，不支持的选项禁用；上游拒绝时显示受控错误，保持原选择。JSON 和 Account 分别保存思考程度；兼容 API 保持原有请求格式。

## 判定边界

- 候选关系按两本作品返回，不接受“整个组都是重复”的决定。
- 现有整包 SHA、逐页内容、附属文件和来源验证继续决定内容等价子组。AI 不写 `eligible`、保留项或隔离映射。
- 作品话数未标注时保持未知，不能推断为第 1 话。`(コミックメガストア Vol.13)` 是刊载来源；整期 `Dascomi Vol.35` 的 35 是刊物期号。
- 作品标题中的 `(COMIC ExE 60)` 是第 60 期刊载来源，整本 `COMIC ExE 60` 是该期杂志。AI 可识别本地未收录的刊名、`春季増刊号` 等文字期号，以及“第三話”“卷之貳”等卷话写法；本地解析结果仅作提示，不构成 AI 可用词汇或格式的白名单。
- 不同期杂志与作品系列分开处理，刊物期次关系单独展示。相同刊名或 AI 的刊物关系不会直接成为内容相同的证据。
- AI 的否定建议不会移除已有内容候选。本地已验证相同内容与 AI 语义判断冲突时会明确提示。
- 语义发现改善别名、多语言和未知编号的召回，但不保证发现所有重编码、改图或元数据完全不同的作品。

## 数据、任务与缓存

AI 只收到成员 ID、标题、作者/社团、语言、作品卷话、刊载信息、版本、实际页数，以及本地内容/来源关系的布尔摘要。不会发送完整路径、实际 hash、来源 token、图库 Cookie、书籍图片或整包文件。

处理流程是：先由 AI 按批次整理全库各本的结构化语义，再由本地候选索引合并原始标题和 AI 归一化别名生成候选，最后向 AI 提交具体两本进行关系判断。单次上游请求只看到当前规范化批次或一个请求配对，不能从未提供的本子推断全库事实；全库覆盖由外层任务、缓存和后续运行共同完成。规范化和配对分类使用不同的 system prompt：前者只负责逐本提取作品、卷话、刊载和版本语义，后者只负责对每个请求配对输出一条关系。分类请求会携带前一步的 `aiHints`，避免重新仅靠本地标题解析；提示只保留作品名、系列名、作者、别名、卷话、刊物和不确定项，且不能当作原文引用。规范化请求返回完整书籍语义，配对分类请求只返回 `relations`（两本 ID、关系枚举、理由），不再要求模型重复填写书籍字段或抄写 `evidenceRefs`。AI 明确返回未知值时，下游保持未知，不用本地旧猜测覆盖。

Key 由 Electron 主进程使用 `safeStorage` 加密，存放在用户数据目录中的 `ai-credentials.json`；两种 ChatGPT 凭据分别加密存放在 `ai-chatgpt-json.json`、`ai-chatgpt-account.json`。旧 SIWC 登录留下的 `ai-oauth-host.json` 不用于新的原生登录。普通设置、worker 参数、审核报告和日志不包含令牌。设置页保存后清空输入，已保存凭据不回填。普通设置保存也不会覆盖独立保存的 AI 配置。

AI 使用独立的非持久 Electron session，并应用应用代理设置，不读取图库登录 Cookie。请求禁止重定向；单请求输入上限 128 KiB，响应上限 1 MiB。兼容 API 的 429、502、503、504 最多重试一次；鉴权失败停止任务，返回格式错误不自动重试。

「流式接收」开关控制兼容 API 的接收方式，默认关闭。开启后发送 `stream: true` 和 `stream_options.include_usage: true`，逐段拼接最终回答，读取最后的 token 用量；忽略思考文本，只将完整回答交给原有 JSON 和语义校验。中断、取消、超时或截断时不保存半截结果，也不自动重放已开始的成功响应。服务器忽略流式并返回普通 JSON 时仍可正常处理；服务器直接拒绝流式时需要关闭开关再测试。ChatGPT (JSON/Account) 通道固定使用 Responses 流式协议，设置页显示为开启且不可修改。切换流式不会使已有单本语义或配对缓存失效，保存后下次请求/任务生效；日志中的 `stream` 标记实际请求方式。流式不直接减少 token，也不改变并发数、批大小或上游限额。

兼容 API 的 SSE 数据块、`[DONE]` 和末尾用量字段按 [DeepSeek Chat Completions 文档](https://api-docs.deepseek.com/api/create-chat-completion/)核对，并以本地模拟服务验证，不向真实模型发送测试书库。

「请求超时」在流式模式下限制等待响应及连续无数据的时间，收到响应或非空数据块后重新计时，持续输出的整次请求可以超过这一秒数；非流式请求和模型列表仍限制整次请求的总时长。两种 ChatGPT 登录方式的流式响应也使用无数据超时。取消请求立即生效，已开始的流式输出不会因超时自动重放。终端请求日志记录 `timeoutMs` 与 `timeoutMode`：`stream_idle` 为流式无数据超时，`request_total` 为整次请求超时。

参考项目批量调用方式的只读分析见 [EH_Archive_tool 批量请求对照](ai-batch-reference.md)。

AI 终端日志和新任务日志的 `at` 使用北京时间，显式带 `+08:00`（例如 `2026-10-17T07:03:34.861+08:00`）。任务日志界面固定按北京时间显示，旧 `Z` 时间仍正常转换，并与新日志按实际时间排序。报告、缓存及任务状态中的内部时间字段保留原有格式。

「每次请求解析本数」和「同时请求数」是两个独立设置，均可设置为 1 到 1000。前者默认 8，仅控制全库发现或系列检查中每次规范化请求包含的本数；配对关系判断仍每次比较两本。后者默认 2，控制规范化和配对判断两个阶段最多同时发送的请求数。例如每请求 8 本、同时请求 25 次，规范化阶段最多同时解析 200 本；剩余任务不足时，并发会相应减少。设置保存后下次分析生效；只修改批次大小或并发数，不使单本语义和配对缓存失效。

分析不再设置单轮请求总数预算，也不在规范化和配对阶段按比例分配请求次数；旧配置中的 `maxRequests` 会被忽略。任务持续处理待解析本子和待判断配对，直到全部完成、用户取消或实际错误停止任务。每个成功单本结果立即写入缓存；批内个别本子校验失败时，先保存其他有效本子，只对失败本子单独重新解析，不再让一处证据错误作废整批。短暂上游错误仍按已有规则重试。重新请求 AI 会绕过缓存。缓存以每一本书为主：书籍元数据、文件身份或语义输入没有变化时，跨服务商和模型复用该书的规范化语义，并记录原服务商和模型；只有发生变化的书重新请求 AI。两本书的关系判断另有配对缓存，配对输入、服务配置、提示词或规则变化时重新判断。语义候选生成和关系判断均不设总量截断；候选分块遍历，配对按需调度，不预先创建全部配对任务。

每次分析绑定输入、服务类型、协议版本、服务地址、实际选中模型、思考程度、返回模式、提示词版本和本地规则版本。全库发现还生成唯一的本轮 `runId`；自动生成审核队列只读取该 `runId` 的成功关系，历史运行结果不会混入本轮。组内建议还绑定原报告、成员和证据版本。书籍元数据、文件状态或报告证据变化后旧建议失效；陈旧发现结果不能导入本地核验。

本地确定性重复检查仍使用第 3 版规则，旧规则的重复报告需要重新检查后再执行。AI 的语义接收独立于该解析规则，不要求本地重新认出刊名或卷话。原有失败记录不会自行变成成功建议，需要重新请求 AI。

AI 提示词和语义接收版本现为第 5 版。规范化结构检查保留字段类型、枚举、有效数值范围、规范年月、已知成员 ID、请求配对及真实输入引用；配对分类只检查关系结构、成员 ID、请求配对和关系内部矛盾，不再要求重复引用原文。分类器发现关系与本地卷话或刊物期次冲突时，程序附加待确认提示，但仍保留该关系供人工审核。规范化中的单章相同起止值统一为 `end: null`，可空文本的空白值统一为 `null`，明确的年月（例如 `2023年9月`、`2023/09`）统一为 `2023-09`。规范化引文必须确实出现在对应原文中；完整结构化引用按 JSON 值比较，允许空格、换行和键顺序变化。引文属实不等于语义已被本地证实，AI 建议仍需审核。提示词升级会使旧语义和配对缓存失效，避免新旧判定规则混用。

已知本地卷话、刊物与 AI 解释不同，以及同作品关系与本地跨卷话信息冲突时，会写入 `uncertainties`，不会使整份 AI 响应失败。未知本地格式不会作为冲突。非法字段、伪造成员 ID、并非输入内容的引文、未请求的配对和 AI 关系内部矛盾仍会拒绝。语义候选进入本地核验后，整包/逐页内容等证据和人工决定继续控制隔离；接收 AI 的新词汇或新格式不会提升隔离资格。

校验失败会保存受控的原因、字段位置及已知成员 ID，并在分析结果中显示；原始消息另存于请求诊断记录，密钥不写入记录。旧失败记录没有这些详情，需要再次分析才能定位。失败结果不进入成功缓存；单本解析的证据或格式错误只对该本重新请求，其他有效结果正常保存。旧版 AI 建议会标记为旧版本；升级不会自动请求 AI。原有保留选择和本地内容核验规则不受此次 AI 接收方式变更影响。

扫描、隔离和 AI 分析共用书库任务锁，AI 请求期间可以阅读与编辑审核草稿。取消会停止新请求，并等待在途请求结束后释放锁。任务异常中断后下次启动显示已中断，已完成结果仍可读取。

AI 状态和建议存储在 `audit/ai/`，推理缓存存储在 `audit-cache.sqlite` 的 `ai_results` 表。清除检查记录会一起清空 AI 结果与缓存，保留服务配置和加密 Key。

## 终端日志

通过启动脚本打开应用时，终端会输出 `[AI]` 事件，包含任务开始/结束、阶段进度、请求开始/结束、缓存命中及结构化结果校验。成功、失败、取消和部分完成会分别标记。日志保留请求编号、服务类型、模型、成员和配对数量、耗时及受控错误位置，不输出令牌、图库路径、完整标题、原始提示词或 AI 原始响应。

下面是模拟测试中的输出格式，数字仅作示例：

```text
[AI] task:start {"at":"2026-10-16T00:00:00.000Z","provider":"compatible","task":"dedupe","model":"fixture-model","status":"running"}
[AI] request:start {"at":"2026-10-16T00:00:00.001Z","requestId":1,"bookCount":2,"pairCount":1,"task":"dedupe"}
[AI] request:finish {"at":"2026-10-16T00:00:00.021Z","requestId":1,"durationMs":20,"status":"completed"}
[AI] result:validated {"at":"2026-10-16T00:00:00.022Z","bookCount":2,"pairCount":1,"warningCount":1,"status":"completed"}
[AI] cache:hit {"at":"2026-10-16T00:00:01.000Z","cachedCount":1,"status":"cached"}
```

结构失败还会输出 `result:invalid`，例如配对关系枚举不合法时显示 `INVALID_VALUE` 和 `relations[0].relation`。规范化引文问题仍会显示具体引文位置；配对分类不再因为模型抄写引文失败而拒绝整组。这些日志用于区分正在请求、复用缓存、结果已接收及结果被结构检查拒绝。

## 实现入口

- `modules/ai_service.js`：HTTP 协议、超时、取消、大小限制及错误处理。
- `modules/ai_credentials.js`：加密凭证存储。
- `modules/ai_oauth.js`：JSON 识别、网页登录回调、身份验证、刷新和退出。
- `modules/ai_responses.js`：SIWC/Codex 请求、账户模型目录和流式结果解析。
- `modules/ai_usage.js`：Codex 额度请求、剩余百分比、窗口与重置时间归一化。
- `modules/ai_logger.js`：终端事件与安全字段白名单。
- `modules/audit/ai_snapshot.js`：轻量数据库元数据快照，不遍历 NAS 压缩包。

## 验证

### 请求记录与批次进度

审核页的任务日志内提供 AI 批次进度及「AI 请求详情」入口。主进程记录运行、阶段、批次、逻辑请求和 HTTP 尝试；终端、审核页及独立窗口使用同一组标识。HTTP 200 后仍需经过完整响应接收、JSON 解析、业务校验及缓存写入，才能显示批次完成。

每批独立统计提交、上游实际返回、校验通过、成功保存、失败及遗漏数量。单本解析按本计数，关系判断按对计数；上游遗漏产生的 unknown 补位不计成功，不写入成功单本缓存或完整批缓存。已存在的同类遗漏缓存也不会阻止重新解析。证据校验按本处理：有效本子立即保存，失败本子单独重新请求，并保留原始错误字段及返回供查看。历史运行的「未请求（达到预算）」仅保留为旧记录状态，新任务不再受该预算限制。

独立窗口显示请求消息、流式原文、解析结果、元信息；原文可切换正文、上游实际返回的思考字段和完整 SSE。按次保留重试记录，失败/取消保留收到的片段。可以暂停实时跟随、搜索当前预览、分段加载、复制预览或导出完整文件。关闭窗口不取消 AI；重新打开恢复记录。观察窗口只有专用只读接口和用户主动导出接口，不具备 AI 设置、登录或任务执行权限。

记录存放于应用数据目录的 `audit/ai/trace/`，按 runId 保存事件 JSONL，并按批次/请求/尝试分别保存消息、SSE、正文、思考字段、JSON 及校验结果。诊断记录与成功语义缓存分开，记录中不保存认证请求头。时间统一显示北京时间。旧运行没有此类记录时，不补造历史请求消息或 token。

流式传输最多接收 32 MiB；提取后的最终 JSON 正文独立限制为 1 MiB，两种接口一致。模型目录等小型非推理数据继续使用 1 MiB 限制。`AI_RESPONSE_TOO_LARGE` 带限制类型、实际字节数和阈值，不会原样自动重发；全库调度停止继续派发新批次，保留已有成功缓存。流式继续使用空闲超时，非流式使用请求总超时。

上游报告的实际 usage 按 HTTP 尝试保存；缓存中的历史 token 不算本次消耗，未提供 usage 时显示未知。原文按需读取，IPC 每 250 ms 合并批次更新，原文接收摘要约每 5 秒打印一次，列表每页渲染 40 条。

### 完整性与补试显示

全库模式先为每本书取得有效单本解析（可跨模型复用缓存），再完整生成候选并判断关系，最后启动本地内容核验和生成审核队列。合法的未知字段可以保存；请求失败或返回遗漏不能当作完成。分析不完整时保留所在阶段并显示继续入口，再次开始只请求未命中有效缓存的项目。

刊物证据可以是输入中的完整对象、对象数组、确切 rawText，或原始标题中的确切摘录；标题引用绑定到实际 title/title_jpn 字段，不受本地刊物解析是否成功限制。提示词与补试提示词采用同一规则。

单本有效结果立即保存；个别成员失败只补试该成员。整批 JSON 无法解析时先拆分补试，补试不额外增加并发。父批次显示首次保存、补试保存和仍未解决数量；所有成员恢复后显示“已恢复”，原错误仍保留在详情。任务概览分别统计缓存、首次保存、补试保存、待补试、最终失败、遗漏和尚未请求。历史预算状态标注为历史任务，当前任务不使用请求总数预算。


### 兼容 API 的思考与输出长度

兼容 API 独立保存 `compatibleReasoningProtocol`（deepseek/openai）、`compatibleThinkingMode`（inherit/disabled/enabled）、`compatibleReasoningEffort`、`compatibleOutputTokenField`（max_tokens/max_completion_tokens）及 `compatibleMaxOutputTokens`。旧配置默认为 inherit、输出长度为 null，不发送这些控制参数。

DeepSeek 协议关闭思考发送顶层 `thinking: {type: "disabled"}`；开启发送 enabled 和所选 low/high/max 等级。OpenAI 协议关闭发送 `reasoning_effort: "none"`，开启发送所选等级。输出长度留空不发送；填写后只发送所选的一个长度字段，不额外设置固定上限。测试连接和分析共用请求构造。上游拒绝这些参数（包括 HTTP 200 中的错误事件）会显示明确错误并停止继续派发同一错误配置，不自动移除参数后重试。第三方网关可能忽略参数，需从实际返回的思考字段和用量确认执行情况。

`finish_reason: length` 与意外流中断分别记录为 length 和 stream_incomplete；保留原始响应、结束原因、实际发送参数和上游报告的思考 tokens。流式响应等待尾部 usage，非流式截断也保留正文与思考原文。

单本解析批次发生 length 截断时，对半拆分失败批次并递归到单本，不受普通证据恢复的两层拆分条件限制。子批在原工作线程内依次执行，仍受全局并发设置约束。成功子批逐本保存；单本仍截断记录 AI_SINGLE_BOOK_TRUNCATED，其他本子继续处理。意外断流、取消、限流不触发长度拆批。不自动提高用户填写的长度，也不将残缺 JSON 修补成成功结果。

更改思考和输出长度不使已有有效缓存失效。新单本缓存来源记录实际请求选项，未知的历史参数不补造。审核队列仍要求全库完整解析和配对判断通过后才进入本地核验。

实测提示：当请求关闭思考，但实际收到非空思考字段或正数思考 tokens 时，请求详情和终端明确标记控制未获预期效果；不将 HTTP 200 作为关闭生效的证明。该提示不否定已经完整返回并通过校验的书籍结果。


### AI 请求 TPS

批次列表、请求详情（随选中的尝试变化）、元信息和终端显示平均 TPS，单位 tokens/s。采用每次 HTTP 尝试的上游输出 tokens 除以该次请求秒数，包含思考 tokens 和首包等待，不包含输入 tokens。思考已计入 completion_tokens，不重复相加；不使用字节数估算 token。

有记录时从 HTTP 尝试开始计时，到完整响应接收结束，排除后续 JSON/业务校验和缓存写入。没有完整响应的失败或取消尝试采用其结束时间；仅在上游报告输出用量时计算。重试独立统计，历史记录使用保存的接收/结束时间恢复 TPS。运行期间用量未知显示“待统计”，终态未报告用量显示“未知”，真实零用量显示 0.00，缓存命中不计算速度。
